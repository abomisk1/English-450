# دليل مختصر لإدارة المحتوى

المحتوى العلمي **منفصل تمامًا عن الشفرة**، فيمكن مراجعته وتحديثه وإضافة الأجزاء القادمة
دون إعادة بناء النظام.

---

## ١) أين يقع المحتوى؟

```
content/
  manifest.json        فهرس البرنامج: الأجزاء، الكتاب المعتمد، الوحدات، الإحصاءات.
  units/u1.json …u7.json   محتوى كل وحدة: الدروس والبطاقات والتفاعلات والأسئلة والمهام.
  needs-review.json    قائمة كل نصّ يحتاج مراجعة واعتمادًا شرعيًّا قبل النشر.
```

`manifest.json` هو الفهرس الذي يقرؤه البرنامج أولًا؛ كل وحدة فيه لها `file` يشير إلى ملفها.

---

## ٢) كيف يُفرَّق بين النصّ الأصلي والشرح والصياغة المساعدة؟

كل عنصر محتوى يحمل حقل `src`، وهو أساس تمييز المصدر في الواجهة وفي المراجعة:

| `src` | المعنى | كيف يظهر في الواجهة |
|---|---|---|
| `book` | نصّ منقول حرفيًّا من الكتاب | لصيقة رمادية: «من الكتاب» |
| `quran` | نصّ قرآني | لصيقة تركوازية: «نصّ قرآني» + إطار مصحفي مميّز |
| `derived` | نشاط أو سؤال مبنيّ حرفيًّا على نصّ الكتاب | داخل صندوق التفاعل، وتفسيره يشير إلى موضعه في الكتاب |
| `authored` | صياغة تعليمية مساعدة ليست من الكتاب | لصيقة صفراء: «صياغة تعليمية مساعدة» |

وكل عنصر `quran` أو `authored` يحمل `needsReview: true` ويظهر تلقائيًّا في
**لوحة إدارة المحتوى والمراجعة الشرعية**.

كل بطاقة تحمل كذلك `page` يشير إلى رقم الصفحة في الكتاب، فيمكن تتبّع مصدر أي نصّ.

## ٣) بنية الدرس

```jsonc
{
  "id": "u1l3",
  "title": "سورة الفاتحة",
  "source": { "book": "al-muhim-li-kulli-muslim", "pages": [8, 9] },
  "hook":      { "text": "مدخل جذّاب…", "src": "authored", "needsReview": true },
  "objective": { "text": "هدف الدرس…",  "src": "authored", "needsReview": true },
  "cards": [
    { "id": "c1", "type": "quran", "src": "quran", "level": "brief",
      "text": "…", "ref": "سورة الفاتحة: ١-٧", "page": 8, "needsReview": true },
    { "id": "c3", "type": "list", "src": "book", "level": "standard",
      "title": "تفسير الآيات", "items": [{ "term": "﴿…﴾", "def": "…" }], "page": 8 }
  ],
  "interactions": [ /* أنشطة أثناء الدرس */ ],
  "summary": { "points": ["…"], "src": "authored", "needsReview": true },
  "quiz":    [ /* الاختبار القصير */ ],
  "family":  { "text": "سؤال نقاش أسري", "src": "authored", "needsReview": true }
}
```

### `type` للبطاقة
`quran` · `hadith` · `dhikr` · `text` · `list` · `note`

### `level` للبطاقة — يتحكّم في أنماط العرض الثلاثة
| `level` | مختصر (≈٥ د) | معتدل (≈١٠ د) | متعمّق |
|---|---|---|---|
| `brief` | ✅ | ✅ | ✅ |
| `standard` | — | ✅ | ✅ |
| `deep` | — | — | ✅ |

> **قاعدة مُلزَمة:** النصّ الشرعي الأساسي (قرآن/حديث/ذكر) يجب أن يكون `brief` دائمًا،
> حتى لا يختلف المحتوى الشرعي بين الفئات، وإنما يختلف مقدار الشرح المصاحب.
> يتحقّق من ذلك اختبار آلي في `tests/run.mjs`.

### أنواع الأسئلة والتفاعلات
`mcq` اختيار · `truefalse` صحيح/خطأ · `order` ترتيب خطوات · `match` مطابقة ·
`complete` إكمال نصّ · `scenario` موقف حياتي · `flashcards` بطاقات تذكّر.

كل سؤال (عدا `flashcards`) يجب أن يحمل `why` يشرح سبب صحة الإجابة أو خطئها،
ويُفضَّل أن يقتبس نصّ الكتاب.

## ٤) كيف أعدّل المحتوى؟

**الطريقة الأولى — تعديل JSON مباشرة (لا تحتاج أدوات):**
افتح `content/units/uN.json`، عدّل، احفظ، ارفع. البرنامج يقرأ الملف كما هو.
إن أضفت عنصرًا جديدًا من نوع `quran` أو `authored`، أضف إليه `"needsReview": true`
وأضف سطره في `content/needs-review.json` (أو أعد التوليد كما في الطريقة الثانية).

**الطريقة الثانية — إعادة التوليد من المصدر المنظَّم:**
```bash
python3 scripts/build_content.py   # يولّد content/*.json و needs-review.json
python3 scripts/build_docs.py      # يولّد docs/CONTENT_MAP.md و docs/NEEDS_REVIEW.md
node tests/run.mjs                 # يتحقّق من سلامة المحتوى
```
مصدر المحتوى المنظَّم في `scripts/content/unit1.py` … `unit7.py`.

---

## ٥) المراجعة الشرعية

افتح `admin/index.html` (عبر خادم ملفات، لا `file://`). تجد فيها:

- **قائمة المراجعة:** كل نصّ يحتاج اعتمادًا، مع تصفية (قرآني / صياغة مساعدة / معتمَد / يحتاج تعديلًا).
  لكل عنصر: **✓ معتمَد** أو **✎ يحتاج تعديلًا** + ملحوظة المراجع.
- **خريطة المحتوى:** جدول بكل وحدة ودروسها وأعداد بطاقاتها وأسئلتها.
- **دليل الإدارة:** ملخّص هذه الصفحة.

قرارات المراجعة تُحفظ في متصفح المراجع، ويُصدّرها بزر **«تصدير قرارات المراجعة»**
إلى ملف `review-decisions.json` للتوثيق.

## ٦) إضافة تسجيل صوتي معتمد

أضف الملف في `assets/audio/`، ثم أضف الحقل إلى البطاقة:

```jsonc
{ "id": "c1", "type": "quran", "…": "…", "audio": "assets/audio/fatiha.mp3" }
```

يتحوّل زرّ الاستماع تلقائيًّا إلى «استماع (تسجيل معتمد)».

> **ضابط مُلزَم في الشفرة:** لا تُقرأ النصوص القرآنية قراءة آلية بأي حال.
> `js/lib/speech.js` يرفض ذلك برمجيًّا، ويتحقّق منه اختباران في `tests/run.mjs`.
> أما الشروح والصياغات التعليمية فيجوز فيها التشغيل الآلي.

---

## ٧) إضافة الجزء الثاني والثالث

1. أضف ملفات وحدات جديدة في `content/units/` (مثل `u8.json`).
2. أضف مدخلها في `content/manifest.json` تحت `units` مع `"part": "part2"`.
3. غيّر حالة الجزء في `parts` من `"planned"` إلى `"published"`.
4. أضف مسارات الملفات الجديدة إلى `SHELL_FILES` في `sw.js` ليعمل دون اتصال،
   وارفع رقم `VERSION` في أعلى الملف ليأخذ المستخدمون النسخة الجديدة.

لا حاجة لتغيير أي شفرة في `js/`.

---

## ٨) ما الذي لا يجوز تغييره؟

- لا تُغيَّر نصوص القرآن أو الأحاديث أو الأذكار.
- لا يُختصر النصّ الشرعي بما يخلّ بمعناه.
- لا يُستبدل النصّ الأصلي بصياغة مولَّدة.
- لا تُضاف فتوى أو حكم أو نسبة علمية غير موجودة في المصدر.
- تبقى نسبة الكتاب إلى مؤلفه كما وردت في المرفق.
- ما تعذّر التحقّق منه يُوضع في قائمة «يحتاج إلى مراجعة»، ولا يُخمَّن.
